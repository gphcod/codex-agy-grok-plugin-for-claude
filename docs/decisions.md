## 2026-10-31 S2: core port

- **S2.4 (recorded with S2.5).** `lifecycle.mjs` re-adds the grok-build `blockingJob` check after every thread claim (A7.8: a lost or cleanup-pending job blocks its thread even when its claim was released); the codex lifecycle the stop path was ported from had dropped it. An expectation in `tests/core-execution.test.mjs` follows the donor rule that on macOS any program path ending in the provider binary name qualifies as the owner of a matching operand (grok-build `lib/execution.mjs:239`); the operand is the job-specific evidence.
- **S2.5 `--commit` uses `diff-tree -M`.** A5.2 names `git diff-tree --no-commit-id -p --root --no-color --no-ext-diff <oid>`; council adds `-M` so a renamed file reads as one rename, as `git diff` (used for `--base` and `--uncommitted`) shows it by default. Without it a rename is a deletion plus an addition and both paths are reported. Touches S4/S5 review prompts only.
- **S2.5 incomplete turn on a review exits 1.** A reader-level `incomplete` (Gemini `print_timeout`) fails every verb with exit 1, reviews included (A3.3: "a print_timeout result is exit 1, never 20"; A5.1). A5.2's `incomplete` verdict (exit 10) is for missing or malformed review output only.
- **S2.5 templates.** `prompts/review.md` and `prompts/adversarial-review.md` are GEMINI's templates made provider-neutral (no "Gemini", no `read_file`, the read-only sentence generic) with one added placeholder, `{{COVERAGE_NOTE}}`, in a `<coverage>` block before the diff. Placeholders: `TARGET_LABEL`, `USER_FOCUS`, `REVIEW_COLLECTION_GUIDANCE`, `COVERAGE_NOTE`, `REVIEW_INPUT`. `interpolate()` substitutes in one pass (diff text containing `{{X}}` is never rescanned) and throws on any template placeholder without a value. `contract.md` is CODEX's contract body unchanged inside `<council_contract version="1">`.
- **S2.5 coverage.** `finalizeReviewTurn` takes `coverage.unreviewed` only from the core's collection and `coverage.reviewed` from the collection when it has one (the adapter's list otherwise, e.g. Codex's native review). An adapter that throws, or returns a result failing `resultProblem`, yields `incomplete` (exit 10).
- **S2.6 optional `checkRequest(request)` on the adapter.** A3.3 says a flag an adapter has no tested mapping for exits 2, and S3.4 wants `--adversarial`/`--web` on Codex refused "before any spawn". The frozen A5 object has no place for that refusal before admission, so it gains one optional method, `checkRequest(request)`, which throws `UsageError`; the entry calls it after resolution and before the request tombstone and the job record. Adapters without it accept every resolved request. S2.7 freezes it with the rest of A5.
- **S2.6 request-id lookup across provider bindings.** A7.3 puts the provider in the claim key, yet A7.4 needs a retry of `reply --last --request-id <id>` to find its first call before `--last` is resolved again. The entry therefore looks the id up under every provider binding of this session and workspace (one hash each) and replays the binding whose recorded fingerprint equals the new call's; with no match it resolves the provider, claims under that binding, and a different fingerprint there exits 2. The fingerprint covers verb, raw options (minus `json`, `request-id`, `session`, `timeout`) and text, as codex-plugin-cc `lib/requests.mjs` does; the reservation (`jobs/<id>/request.json`) carries it too, so a concurrent identical call waits on the first instead of failing.
- **S2.6 resolution details.** `task` without `--tier` uses the `exec` tier (grok-build `rescue` default); `reply` inherits the thread's tier, model and effort unless one is given (A3.2); a thread whose record names another workspace exits 2 (A7.3 "never adopted across workspaces"; grok-build ran the turn in the recorded cwd instead); a review job is not a thread to reply to. `loadCatalog` accepts an adapter's own static entry so the test-only null adapter needs no row in `models.json`; `refreshCatalog` checks the provider name's form instead of the three-provider list.
- **S2.6 test seams.** The fake child logs its prompt bytes and the guard variables it received in the spawn log; the null adapter returns no launcher when its entry file is missing, reads `COUNCIL_NULL_CONSULT` for its consult tier and `COUNCIL_NULL_NO_WEB` for `checkRequest`, so tests can change tiers between a call and its replay and exercise the refusal path.
- **S2.7 A5 `beforeTurn`/`afterTurn` wired.** The core calls `beforeTurn({job, request, turn, home})` once after admission and before the spawn (a throw fails the turn with nothing started) and `afterTurn(ctx, {outcome, code, error})` once after finalization, only when cleanup was verified (also after a failure or cancellation); an `afterTurn` throw is stored as `afterTurnError` and does not change the result. No adapter in this host uses them in 1.0.
- **S2.7 ratio.** `--ratio` reached 1.51 (3887 / 2579) with tests of real core behaviour; an lcov branch report over `tests/core-*.test.mjs` and `catalog.test.mjs` showed 99 % line and about 93 % branch coverage of `lib/core/` before the last additions, which then targeted the uncovered branches (A7.8 blocking, spawn races, launch storage failure, /proc and PowerShell failures, file-system helpers, catalog corners, shutdown budget). `catalog.test.mjs` keeps its A4 name and so does not count toward the ratio, although it tests `catalog.mjs` and `tiers.mjs`.

- **S2 ports not taken whole.** GEMINI `buildCollectionGuidance` is ported provider-neutral without its "complete diff in a file, read it with read_file" branch: council never writes an oversized diff for the model to page through; whatever exceeds the inline cap is named in the prompt and reported as `coverage.unreviewed` (exit 10), per A5.2. CODEX `waitsForCodex` and the qualified launcher kinds move to the codex adapter's `trustsCleanExit` (S3.1). The grok-build `GROK_BUILD_ROUNDS` / codex `CODEX_COMPANION_ROUNDS` default-budget variable is `COUNCIL_ROUNDS`. The grok-build `requests/` ledger is replaced by the A7.4 tombstone under `claims/requests/`, and its `NEW_ID` placeholder check is not ported (the skill convention in A3.3 is 8 random characters, written in S6).

## 2026-10-31 S2 freeze

Frozen from commit `S2.7: freeze` on; any later change needs an entry here and a review by one of the three models (Codex, Gemini, Grok):

- **A5 adapter object** with its return shapes, written as JSDoc typedefs in `plugins/council/scripts/lib/core/types.mjs`: `id`, `binEnv`, `resolveLauncher(env, platform) → {command, args, path, kind}|null` (kind ∈ native, node-script, shim-native, shim-node), `trustsCleanExit(launcher) → boolean`, `ownsProcess(row, job, platform) → boolean` (via `hasFlagOperand`), `maxLineBytes`, `probe(launcher) → {version, loggedIn, models: [{id, efforts}]}`, `catalog`, `buildTurn(request + {jobId, jobDir}) → {args, env, stdin | promptFile + promptText, answerFile|null, readOnly, agent?, contractCarrier, threadId?}`, optional `checkRequest(request)` (throws UsageError, exit 2, before any job), optional `beforeTurn`/`afterTurn`, `parseEvent(line, state) → {threadId?, textDelta?, toolStep?, completed?, fatal?, denied?, incomplete?, structured?, edited?, failedCommand?, costUsd?, usage?, error?}|null`, `reviewPlan(gitInfo{root, target, collect()}, request) → {native: true, flags, stdin} | {native: false, diff, template, schemaCarrier}`, `finalizeReview({answerText, structured, unreviewed}) → A5.2 result + renderedText?/summary?/nextSteps?`.
- **Exit codes** 0 done, 10 needs attention, 20 still running, 1 failed/cancelled/busy, 2 invalid input (`EXIT` in `types.mjs`).
- **Start line** (stderr, not under `--json`): `[council] provider=<p> job=<id> thread=<native id|?>[ target=<label>]`; a replay appends ` replay=<request id>`.
- **Footer** (stdout, one line): `council <provider> <ok|needs attention|failed|cancelled> · job <16 chars> · <model>/<effort>[<=requested] · <duration>[ · round N/M][ · edited N][ · unreviewed N][ · model unverified][ · full: <file>][ · error: <msg>][ · <recovery hint>]`, the recovery hint being `thread locked: …`, `cleanup pending; next: cancel <job>; do not resume`, or `next: reply <job>` (never on a review).
- **`--json` object**: `provider, job, thread, session, model, modelVerified, effort, requestedEffort, tier, round, rounds, verdict, findings, coverage, edited, failedCommands, costUsd, exit, answerFile`, plus `verb, status, elapsedMs, error, cleanupPending, answer, clipped`.
- **Normalized review result** (A5.2): `{verdict: approve|changes|incomplete, findings: [{severity: BLOCKER|MAJOR|MINOR, file, line, lineEnd?, title, text, recommendation?, confidence?}], coverage: {reviewed, unreviewed}, incomplete: reason|null}`; exit 10 whenever findings exist, coverage is incomplete, the output is incomplete or malformed, or the verdict is not a clean approval.
- **State layout** under `COUNCIL_HOME` (default `~/.council`): `jobs/<16 chars>/{meta.json, beat, done, stopped, cancel, answer.md, events.jsonl, prompt.md?, settings.json?, request.json?, cleanup-evidence/}`, `claims/<provider>/<thread>/owner-<token>`, `claims/requests/<job>.json` (immutable tombstone), `threads/<provider>-<thread>.json` (never pruned), `catalog/<provider>.json`, `trash/`.
- **Dynamic provider registry**: `plugins/council/scripts/lib/providers/<id>.mjs`, found by `fs.existsSync` and loaded by `import()`, default export the adapter with `id` equal to the file name; absent → exit 2 `provider <p> not available in this build`. The test-only `null` provider loads from `tests/fixtures/null-adapter.mjs` when `COUNCIL_TEST_NULL_ADAPTER=1`. S3–S5 add only their module, tests and records and never edit `council.mjs`.
